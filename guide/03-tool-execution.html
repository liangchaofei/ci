第 03 篇：请求一个工具，不等于可以直接执行 ​

第 2 篇已经连起“最新状态 → 本轮输入 → 决策”。现在，脚本提出 read_source 请求，循环就调用场景提供的读取函数。但如果请求的工具根本没有注册，或者 path 变成了数字，应该由谁阻止它？

本篇补上工具执行入口：先按名称找到工具，再检查参数，最后才允许进入具体操作。你会先独立运行一个工具，看到合法参数能够进入读取体、错误参数被提前挡住；随后将它接回原有循环，观察成功和失败怎样成为下一轮输入。

要理解的核心关系是：模型提出请求，应用提供工具，执行入口检查并调用，循环记录结果。 本篇会实现工具定义、参数检查、注册表与统一结果包装。循环、State 和 Context 继续使用前两篇的代码。读取仍返回固定源码，决策仍由脚本模拟；真实文件读写、模型接口、审批、超时和取消尚未实现。

先看一次请求要经过哪里 ​

继续诊断同一个问题：sum([]) 为什么失败。脚本先提出以下请求，这是数据，还没有发生读取：

json
{
  "id": "read-1",
  "name": "read_source",
  "arguments": { "path": "src/sum.ts" }
}

name 表示“要用哪种工具”，id 表示“这是哪一次调用”。同一个工具可以被调用很多次，每次结果需要回到对应请求。当前固定场景只调用一次，所以沿用 read-1；以后多次调用时还需要管理各次身份。

正常情况下，read_source 找到已注册的读取工具，{ path: "src/sum.ts" } 通过检查，读取体交回源码。执行入口再补上原请求的 callId，循环把结果保存为 tool 消息。下一轮 Context 才会包含它。

如果参数是 { path: 42 }，名称仍然能找到工具，但参数检查失败，读取体不会被调用。执行入口交回带 invalid-arguments 的错误结果，循环同样记录它。脚本因此知道“没拿到可用源码”，而不是误以为读取成功。

为什么要从原函数中抽离 ​

上一章的 simulateReadSource 把工具名判断、参数检查、模拟读取和结果包装放在一个函数里。只处理固定读取时容易理解；再增加搜索、写文件等工具，这个函数就需要知道所有工具的规则。

本篇按变化原因拆分：工具各自定义参数和操作；注册表只查名称；执行入口统一包装结果。循环仍只安排调用、核对调用身份并写回状态，不增加读取路径等场景知识。

这里的契约是模块之间约定的输入、输出和行为。例如“执行入口接收 ToolCall，返回带同一调用 ID 的 ToolResult”。类型帮助检查代码是否遵守约定，运行时的参数检查则负责核实本次实际收到的数据。

第一阶段：先让一个工具检查参数 ​

先完成这一阶段并运行，再进入注册与集成。此时上一章入口继续使用旧读取器，新工具还没有接入循环。

1. 定义工具接收什么、返回什么 ​

新建 src/runtime/tool.ts，写入以下类型。下一步在同一文件末尾追加函数。

ts
/** 校验成功时交出已确认的参数；失败时不提供可执行参数。 */
export type ParseResult<Args> =
  | { ok: true; value: Args }
  | { ok: false; message: string };

/** 工具内部输出不带调用身份，身份由统一执行入口添加。 */
export type ToolOutput =
  | { status: "ok"; value: unknown }
  | { status: "error"; code: "invalid-arguments"; message: string };

/** 注册表持有的工具入口，原始输入必须经过 invoke 中的校验。 */
export type Tool = {
  readonly name: string;
  readonly invoke: (input: unknown) => Promise<ToolOutput>;
};

/** 同一个 Args 连接校验结果与执行体的参数。 */
export type ToolDefinition<Args> = {
  name: string;
  parse: (input: unknown) => ParseResult<Args>;
  execute: (args: Args) => Promise<unknown>;
};

先用本例的具体值理解：参数正确时，检查函数交回 { ok: true, value: { path: "src/sum.ts" } }；参数错误时，交回 { ok: false, message: "path must be a non-empty string" }。这两种形状由 ParseResult 描述。失败分支没有 value，调用方不能把它当成已确认的参数。

Args 是“这个工具检查通过后，参数是什么类型”的占位名称。读取工具会用 { path: string } 替换它。ToolDefinition<Args> 中 parse 交出的 value 和 execute 接收的 args 使用同一个类型，避免二者各说各话。这是泛型在这里的用途，不必先记住抽象定义。TypeScript：泛型函数连接输入与输出类型

ToolDefinition 是定义工具所需的三项配置：名称、参数检查函数、具体执行函数。注册表最终只需要一个统一入口，所以 Tool 只公开 name 和 invoke；各工具内部参数类型可以不同，外部都从 invoke 进入。

invoke 接收 unknown：调用者可以交入数据，但工具不能未经判断就按字符串读取 path。与 any 不同，unknown 要求先确认数据的形状，才能使用其中字段。TypeScript 类型声明不会在程序运行时自动替你检查数据，本阶段接下来会写真实的检查语句。

ToolOutput 是工具内部的返回值：成功带 value，参数失败带错误代码和说明。此时工具只知道参数，不需要负责 read-1 这样的调用身份。第二阶段的执行入口会添加它。Tool、ToolOutput 这些类型也不会自己创建对象；实际对象由下面的函数产生。

2. 确保检查成功后才执行 ​

在 src/runtime/tool.ts 的类型定义后追加完整函数：

ts
/** 封装校验顺序，使执行体只接收 parse 成功产出的参数。 */
export function defineTool<Args>(definition: ToolDefinition<Args>): Tool {
  return {
    name: definition.name,
    async invoke(input) {
      const parsed = definition.parse(input);
      if (!parsed.ok) {
        return { status: "error", code: "invalid-arguments", message: parsed.message };
      }

      const value = await definition.execute(parsed.value);
      return { status: "ok", value };
    },
  };
}

之后调用 readSourceTool.invoke({ path: "src/sum.ts" }) 时，先运行定义中的 parse。拿到 ok: true 后，parsed.value 已经是读取工具要求的参数，再传给 execute。await 等待执行完成，最终把源码包装成 { status: "ok", value: 源码 } 返回。

这个顺序由 defineTool 统一安排。工具作者提供检查规则和操作，调用者不必先记得手工检查一次、再调用另一个读取函数。不同工具复用同一入口顺序。

如果 parse 返回 ok: false，函数当场 return 错误对象，后面的 execute 根本不会运行。检查后返回失败，与执行后报告失败，是两个时刻。 写文件等操作一旦开始可能已经产生影响，所以后续接入真实工具时，检查的位置尤其关键。

这里没有 catch。检查函数意外抛错或执行体抛错，都会使 invoke 返回的 Promise 失败；第二阶段统一执行入口会将这类异常包装为工具错误。参数被规则拒绝则是正常返回的错误对象，二者走的路径不同。

4. 编写读取参数的检查规则 ​

新建 src/examples/read-source-tool.ts，先写导入：

ts
import { defineTool } from "../runtime/tool.ts";
import type { ParseResult } from "../runtime/tool.ts";
import { sourceCode, sourcePath } from "./diagnosis-fixture.ts";

紧接着追加类型和完整函数：

ts
/** 本例读取体只接受这一种已经校验的参数。 */
type ReadSourceArgs = { path: string };

function parseReadSourceArgs(input: unknown): ParseResult<ReadSourceArgs> {
  if (typeof input !== "object" || input === null || Array.isArray(input)) {
    return { ok: false, message: "Arguments must be an object" };
  }
  if (!("path" in input) || typeof input.path !== "string" || input.path.trim() === "") {
    return { ok: false, message: "path must be a non-empty string" };
  }
  if (Object.keys(input).some((key) => key !== "path")) {
    return { ok: false, message: "Unexpected argument" };
  }
  if (input.path !== sourcePath) {
    return { ok: false, message: "Source path is not allowed" };
  }

  // 返回新对象，执行体不再直接接收未确认的原始输入。
  return { ok: true, value: { path: input.path } };
}

先沿正常输入走一遍。{ path: "src/sum.ts" } 是非 null、非数组的对象；它有非空字符串 path，没有其他字段，而且 path 等于本例允许的 sourcePath。最后返回一个新的 { path: input.path }，供读取体使用，而不是直接把原始 input 塞过去。

每一层判断都解决一个具体问题：

检查位置拦下的例子原因
对象形状null、数组、数字这些都不是本工具约定的参数对象
path 存在且为非空字符串{}、{ path: 42 }、{ path: " " }读取体需要有意义的字符串路径
没有额外字段{ path: "src/sum.ts", force: true }本工具未定义 force，不能默默接受并让调用者误以为它生效
等于演示路径{ path: "src/other.ts" }模拟读取只认识固定源码，不能对任何路径都返回同一段内容

typeof null 的结果也是 "object"，数组也是对象，因此第一层要分别排除它们。通过后，"path" in input 确认字段存在，typeof input.path === "string" 才允许后续使用 trim。条件通过短路求值从左到右检查，未确认字符串前不会调用 trim。TypeScript：通过判断收窄类型

Object.keys(input).some(...) 检查字段名中是否存在任何非 path 的项；存在就拒绝。最后一层则核对字符串的具体值，所以“path 是字符串”与“这个路径在本例允许范围”是两件事。

这份解析器接受的是普通请求数据，明确构造新的已确认参数。不使用 as ReadSourceArgs 强行让类型检查器相信它正确。固定路径限制只是本场景的规则；它没有实现操作系统隔离、真实路径解析或完整的文件访问权限。

5. 组装可调用的读取工具 ​

在 src/examples/read-source-tool.ts 末尾追加：

ts
/** 仍是模拟读取；执行日志只出现在校验通过后的工具体中。 */
export const readSourceTool = defineTool<ReadSourceArgs>({
  name: "read_source",
  parse: parseReadSourceArgs,
  async execute(args) {
    console.log(`[执行工具 execute] read_source 文件路径（path）=${args.path}`);
    return sourceCode;
  },
});

defineTool<ReadSourceArgs> 把“检查成功后的参数是 { path: string }”这件事同时告诉 parse 和 execute。创建 readSourceTool 时只是保存函数，没有执行读取；真正调用 invoke 才会进入上一步的检查流程。

async execute(args) 是具体读取体。它只在检查通过后运行，因此这里可以直接使用 args.path。日志放在执行体内部，便于观察请求是否到达了实际操作位置；返回的仍是固定 sourceCode，并没有调用文件系统。

现在的分工是：parse 判断数据是否符合本工具规则，execute 完成具体操作，defineTool 保证两者按顺序发生。以后将模拟体换成真实读取，检查与调用顺序仍需要保留。

7. 给工具失败增加可识别的代码 ​

在 src/runtime/types.ts 中，用下面整段替换原 ToolResult 定义，将 ToolErrorCode 放在它前面。其他类型保留。

ts
/** 可由程序区分的工具失败原因，不依赖错误文字匹配。 */
export type ToolErrorCode = "unknown-tool" | "invalid-arguments" | "tool-error";

/** 工具观察始终关联原请求；错误也会进入下一轮输入。 */
export type ToolResult =
  | { callId: string; status: "ok"; value: unknown }
  | { callId: string; status: "error"; code: ToolErrorCode; message: string };

本项目用三个固定值区分工具失败：unknown-tool 表示找不到工具，invalid-arguments 表示参数未通过规则，tool-error 表示检查或执行过程中出现了异常。这是本教程的内部协议，不是模型服务要求的统一标准。

例如数字路径的最终结果会是：

json
{
  "callId": "read-1",
  "status": "error",
  "code": "invalid-arguments",
  "message": "path must be a non-empty string"
}

code 给程序稳定的分类，message 提供具体说明。之后不能通过判断错误文字中是否含某个词来推测种类。成功分支保持原样；判断 result.status === "error" 后才能读取 code 和 message。

ToolOutput 与 ToolResult 也有明确区别：前者是工具入口内部返回值，后者带 callId，可以交给循环关联和记录。本阶段会在二者之间补上包装。

8. 建立工具名称索引 ​

新建 src/runtime/tool-registry.ts，先写以下导入：

ts
import type { Tool } from "./tool.ts";

然后追加注册表的公开接口：

ts
/** 只公开查找和列名，不允许调用方直接修改内部 Map。 */
export type ToolRegistry = {
  get: (name: string) => Tool | undefined;
  names: () => string[];
};

注册表就是一张“名称对应哪个工具入口”的表。get("read_source") 要么取得 Tool，要么得到 undefined；names 用于显示已经注册哪些名称。它保存可调用的程序能力，与 State 中记录“先前发生了什么”的消息不是同一类数据。

在同一文件末尾追加完整创建函数：

ts
/** 启动时建立名称索引；重复名称是配置错误，不能静默覆盖。 */
export function createToolRegistry(tools: readonly Tool[]): ToolRegistry {
  const byName = new Map<string, Tool>();

  for (const tool of tools) {
    if (tool.name.trim().length === 0) {
      throw new Error("Tool name must not be empty");
    }
    if (byName.has(tool.name)) {
      throw new Error(`Duplicate tool: ${tool.name}`);
    }
    // 保存名称与入口的当前值，而不是交出可变的注册对象。
    byName.set(tool.name, { name: tool.name, invoke: tool.invoke });
  }

  return {
    get: (name) => byName.get(name),
    names: () => [...byName.keys()],
  };
}

应用调用 createToolRegistry([readSourceTool]) 后，函数内部创建 byName，并把 read_source 对应的名称和 invoke 存进去。返回对象中的 get 继续使用这张 Map；创建函数返回后，Map 仍被这些函数引用，因此后续还能查找。这种让函数保留外层局部变量的关系称为闭包。

byName 没有被直接交给外部。调用者可以查工具或取得名称列表，不能通过这个接口调用 Map.set 随意注册新工具。names 每次产生一个新数组，修改返回数组不会改变索引。这里限制的是公开操作，不宣称对象被深度冻结。

重复注册 read_source 时直接抛错。如果静默覆盖，实际执行哪个入口就取决于配置排列顺序，错误很难发现。空名称也拒绝；其他名称按原值精确匹配，不自动改大小写或去掉两端空格。

注册发生在任务开始前，所以重复名称属于应用配置错误，不包装成某次模型调用的工具失败。修复方式是检查注册清单。它与运行中收到未知工具请求的处理位置不同。

9. 实现统一执行入口 ​

新建 src/runtime/tool-executor.ts，写入完整文件：

ts
import type { ToolCall, ToolResult } from "./types.ts";
import type { ToolRegistry } from "./tool-registry.ts";

/** 将注册表接到原有 executeTool 接口，不持有或更新 State。 */
export function createToolExecutor(
  registry: ToolRegistry,
): (call: ToolCall) => Promise<ToolResult> {
  return async (call) => {
    const tool = registry.get(call.name);
    if (!tool) {
      return {
        callId: call.id,
        status: "error",
        code: "unknown-tool",
        message: `Unknown tool: ${call.name}`,
      };
    }

    try {
      const output = await tool.invoke(call.arguments);
      // 工具只处理参数与值；调用身份统一取自原请求。
      return { ...output, callId: call.id };
    } catch (error) {
      return {
        callId: call.id,
        status: "error",
        code: "tool-error",
        message: error instanceof Error ? error.message : String(error),
      };
    }
  };
}

先看创建和调用这两个时刻：createToolExecutor(registry) 只返回一个函数；随后 executeTool(call) 才根据这次 call 查工具并执行。返回函数保留 registry，因而每次调用不必再传整张表。

用本例走正常路径：

  1. registry.get(call.name) 用 read_source 查到 Tool。
  2. tool.invoke(call.arguments) 把 { path: "src/sum.ts" } 交给已写好的检查入口。
  3. invoke 完成检查和读取，交回 { status: "ok", value: 源码 }，由 output 接住。
  4. { ...output, callId: call.id } 创建带原请求身份的新结果，返回给调用方。

执行器内的 output 是 ToolOutput，循环内接住返回值的 result 才是 ToolResult。return 只把对象交回去，此函数没有 State，也不会自己追加消息。

失败有三个位置。查不到名称时，在调用 invoke 前返回 unknown-tool。检查返回拒绝时，invoke 正常交回 invalid-arguments，执行器为它补上 callId。检查函数或执行体抛出异常时，才进入 catch，返回 tool-error。catch 用 Error.message 或 String(error) 取得说明，不把任意抛出值都假定为 Error。

callId 始终取自原请求，工具体不用自己生成它。循环原有的对应关系检查仍保留：executeTool 是外部依赖，不能因为本入口正确包装，就删掉循环边界的核对。

本入口现在接收项目内部的 ToolCall；它没有检查来自网络的整份未知 JSON 是否真是 ToolCall。以后接入模型时，会在适配边界处理动作形状。此处补的是工具参数运行时检查，不能用 TypeScript 声明代替外部数据校验。

ts
/** 校验成功时交出已确认的参数；失败时不提供可执行参数。 */
export type ParseResult<Args> =
  | { ok: true; value: Args }
  | { ok: false; message: string };

/** 工具内部输出不带调用身份，身份由统一执行入口添加。 */
export type ToolOutput =
  | { status: "ok"; value: unknown }
  | { status: "error"; code: "invalid-arguments"; message: string };

/** 注册表持有的工具入口，原始输入必须经过 invoke 中的校验。 */
export type Tool = {
  readonly name: string;
  readonly invoke: (input: unknown) => Promise<ToolOutput>;
};

/** 同一个 Args 连接校验结果与执行体的参数。 */
export type ToolDefinition<Args> = {
  name: string;
  parse: (input: unknown) => ParseResult<Args>;
  execute: (args: Args) => Promise<unknown>;
};

/** 封装校验顺序，使执行体只接收 parse 成功产出的参数。 */
export function defineTool<Args>(definition: ToolDefinition<Args>): Tool {
  return {
    name: definition.name,
    async invoke(input) {
      const parsed = definition.parse(input);
      if (!parsed.ok) {
        return { status: "error", code: "invalid-arguments", message: parsed.message };
      }

      const value = await definition.execute(parsed.value);
      return { status: "ok", value };
    },
  };
}

import type { Tool } from "./tool.ts";

/** 只公开查找和列名，不允许调用方直接修改内部 Map。 */
export type ToolRegistry = {
  get: (name: string) => Tool | undefined;
  names: () => string[];
};

/** 启动时建立名称索引；重复名称是配置错误，不能静默覆盖。 */
export function createToolRegistry(tools: readonly Tool[]): ToolRegistry {
  const byName = new Map<string, Tool>();

  for (const tool of tools) {
    if (tool.name.trim().length === 0) {
      throw new Error("Tool name must not be empty");
    }
    if (byName.has(tool.name)) {
      throw new Error(`Duplicate tool: ${tool.name}`);
    }
    // 保存名称与入口的当前值，而不是交出可变的注册对象。
    byName.set(tool.name, { name: tool.name, invoke: tool.invoke });
  }

  return {
    get: (name) => byName.get(name),
    names: () => [...byName.keys()],
  };
}

import type { ToolCall, ToolResult } from "./types.ts";
import type { ToolRegistry } from "./tool-registry.ts";

/** 将注册表接到原有 executeTool 接口，不持有或更新 State。 */
export function createToolExecutor(
  registry: ToolRegistry,
): (call: ToolCall) => Promise<ToolResult> {
  return async (call) => {
    const tool = registry.get(call.name);
    if (!tool) {
      return {
        callId: call.id,
        status: "error",
        code: "unknown-tool",
        message: `Unknown tool: ${call.name}`,
      };
    }

    try {
      const output = await tool.invoke(call.arguments);
      // 工具只处理参数与值；调用身份统一取自原请求。
      return { ...output, callId: call.id };
    } catch (error) {
      return {
        callId: call.id,
        status: "error",
        code: "tool-error",
        message: error instanceof Error ? error.message : String(error),
      };
    }
  };
}

/** 模型提出的工具请求；id 标识一次调用，name 标识工具种类。 */
export type ToolCall = {
  id: string;
  name: string;
  arguments: Record<string, unknown>;
};

/** 可由程序区分的工具失败原因，不依赖错误文字匹配。 */
export type ToolErrorCode = "unknown-tool" | "invalid-arguments" | "tool-error";

/** 工具观察始终关联原请求；错误也会进入下一轮输入。 */
export type ToolResult =
  | { callId: string; status: "ok"; value: unknown }
  | { callId: string; status: "error"; code: ToolErrorCode; message: string };

/** 模型提出的请求。finish 仍要经过应用的完成验证。 */
export type Action =
  | { kind: "tool"; call: ToolCall }
  | { kind: "finish"; answer: string }
  | { kind: "fail"; reason: string };

/** 本章的最小会话记录，按发生顺序追加。 */
export type Message =
  | { role: "user"; content: string }
  | { role: "assistant"; action: Action }
  | { role: "tool"; result: ToolResult };

/** 一次运行的当前事实；不同运行不能共享这个对象。 */
export type State = {
  goal: string;
  messages: Message[];
  decisions: number;
};

/** 本轮决策可见的输入；控制字段仍由 Runtime 持有。 */
export type DecisionContext = {
  readonly messages: readonly Message[];
};

/** Runtime 的退出原因，与会话里保留的事实分别表达。 */
export type Outcome =
  | { status: "completed"; answer: string }
  | {
      status: "failed";
      reason: string;
      source: "decision" | "execution" | "validation";
    }
  | { status: "budget-exhausted" };

export type RunResult = { state: State; outcome: Outcome };

/** 由调用方提供模型、工具和任务完成规则，循环只负责调度。 */
export type Dependencies = {
  // 只接收本轮准备好的消息，不接收 Runtime 的控制字段。
  decide: (context: DecisionContext) => Promise<Action>;
  // 取得一次请求的实际结果，必须回传同一个调用 ID。
  executeTool: (call: ToolCall) => Promise<ToolResult>;
  // 核对当前场景的完成证据，不把模型的 finish 直接当成成功。
  validateFinish: (state: Readonly<State>, answer: string) => boolean;
};

src/runtime/agent-loop.ts ​

ts
import { buildDecisionContext } from "./context.ts";
import type {
  Action,
  Dependencies,
  Outcome,
  RunResult,
  State,
  ToolResult,
} from "./types.ts";

/** 保护循环拥有的消息；当前 State 只包含可结构化复制的数据。 */
function snapshot(state: State): Readonly<State> {
  // 依赖只能改自己的副本；不能修改 Runtime 留存的消息。
  return structuredClone(state);
}

function failure(reason: string, source: "decision" | "execution" | "validation"): Outcome {
  return { status: "failed", reason, source };
}

function errorMessage(error: unknown): string {
  return error instanceof Error ? error.message : String(error);
}

/**
 * 驱动一次任务，并返回最后状态与退出原因。
 * maxDecisions 限制取得 Action 的次数；一次决策最多请求一个工具。
 */
export async function runAgentLoop(
  goal: string,
  dependencies: Dependencies,
  maxDecisions: number,
): Promise<RunResult> {
  if (!Number.isInteger(maxDecisions) || maxDecisions < 1) {
    throw new RangeError("maxDecisions must be a positive integer");
  }

  // State 只属于这次调用；再次运行会得到新的消息与计数。
  let state: State = {
    goal,
    messages: [{ role: "user", content: goal }],
    decisions: 0,
  };

  while (state.decisions < maxDecisions) {
    let action: Action;
    try {
      // 每轮都重新构造，才能包含上一轮刚写回的工具结果。
      const context = buildDecisionContext(state);
      action = structuredClone(await dependencies.decide(context));
    } catch (error) {
      return { state, outcome: failure(errorMessage(error), "decision") };
    }

    // 先记下模型提出了什么，再判断能否执行或完成。
    state = {
      ...state,
      decisions: state.decisions + 1,
      messages: [...state.messages, { role: "assistant", action }],
    };

    if (action.kind === "fail") {
      return { state, outcome: failure(action.reason, "decision") };
    }

    if (action.kind === "finish") {
      try {
        // 模型的完成请求不是成功事实，必须交给应用规则核对。
        if (dependencies.validateFinish(snapshot(state), action.answer)) {
          return { state, outcome: { status: "completed", answer: action.answer } };
        }
        return { state, outcome: failure("Completion lacks verified evidence", "validation") };
      } catch (error) {
        return { state, outcome: failure(errorMessage(error), "validation") };
      }
    }

    let result: ToolResult;
    try {
      result = structuredClone(await dependencies.executeTool(structuredClone(action.call)));
    } catch (error) {
      // 执行错误也是观察，下一轮决策需要知道这次调用失败了。
      result = { callId: action.call.id, status: "error", code: "tool-error", message: errorMessage(error) };
    }

    // 一个调用的结果不能写到另一个调用名下。
    if (result.callId !== action.call.id) {
      return {
        state,
        outcome: failure("Tool result callId does not match the request", "execution"),
      };
    }

    // 只有确认属于本次调用的结果才能进入 State，供下一轮 decide 使用。
    state = { ...state, messages: [...state.messages, { role: "tool", result }] };
  }

  return { state, outcome: { status: "budget-exhausted" } };
}

/** 按状态返回预设动作，扮演模型；不能分析任意源码。 */
export async function scriptedDecide(context: DecisionContext): Promise<Action> {
  const roles = context.messages.map((message) => message.role).join(" -> ");
  console.log(`[决策 decide] 消息角色（roles）=${roles}`);

  const lastMessage = context.messages.at(-1);
  if (lastMessage?.role === "user") {
    // 这里只提出请求，注册查找与参数检查由执行入口安排。
    return { kind: "tool", call: createReadSourceCall() };
  }

  if (
    lastMessage?.role === "tool" &&
    lastMessage.result.callId === sourceCallId &&
    lastMessage.result.status === "ok" &&
    lastMessage.result.value === sourceCode
  ) {
    return { kind: "finish", answer: diagnosis };
  }

  return { kind: "fail", reason: "No usable source observation" };
}

/** 核对固定诊断与固定读取证据，不证明任意代码诊断正确。 */
export function hasDiagnosisEvidence(state: Readonly<State>, answer: string): boolean {
  if (answer !== diagnosis) return false;

  return state.messages.some((message) => {
    if (message.role !== "tool") return false;

    return (
      message.result.callId === sourceCallId &&
      message.result.status === "ok" &&
      message.result.value === sourceCode
    );
  });
}
