第 05 篇：让真实模型决定下一步 ​

前四篇里，scriptedDecide 遇到 user 就提出读取，看到预期源码就给出固定答案。循环、工具检查和停止控制都在运行，但下一步已经被脚本写好。本篇把这个位置换成 DeepSeek 官方 API：模型接收本轮消息与工具说明，决定请求工具还是回答。

先用一个很短的入口确认“请求发出，服务返回”；再把同一个 HTTP 函数接到已有 Runtime。完成后，诊断任务应经历：模型要求读取 src/sum.ts → 本地工具返回源码 → Runtime 写回 → 下一次模型请求包含源码 → 模型给出诊断。模型是真实的，读取体仍返回固定源码；本篇没有实际修改文件。

本篇要理解的主线是“内部消息怎样变成接口请求，接口响应怎样变成内部动作”。循环与停止控制继续复用，不在模型适配器里再写一套循环。暂不处理流式输出、思考内容、多工具批次或自动重试。

推荐分支与运行前提 ​

从第 4 篇已验证、已提交的本地版本创建：

bash
git switch -c codex/chapter-05-deepseek

若分支已存在，用 git switch codex/chapter-05-deepseek 返回。命令均在仓库根目录执行。继续使用 Node 22.18 或更新版本及原有依赖，不安装模型 SDK；HTTP 请求使用 Node 自带 fetch。

本篇选定 DeepSeek 官方的 Chat Completions 接口、非思考模式，示例模型名为 deepseek-flash。这是编写时官方文档列出的模型名；模型可用性与账户状态仍以服务实际返回为准，不沿用旧文章中的 deepseek-chat 名称。官方模型列表

验证范围

本篇的类型、消息转换、模拟 HTTP 两轮交互、错误与取消路径已在独立候选工程验证。真实服务调用还需要本地有效密钥与可用账户；联网运行以你的实际结果为准。下方标为“典型轨迹”的模型输出用于解释流程，不是固定答案或逐字承诺。

2. 写只负责 HTTP 的函数 ​

新建目录 src/adapters/deepseek/，在其中新建 http.ts，写入完整代码：

ts
/** 只发送请求并取得未知 JSON；不执行工具，也不修改运行状态。 */
export async function requestDeepSeek(
  apiKey: string,
  body: Record<string, unknown>,
  signal: AbortSignal,
): Promise<unknown> {
  if (!apiKey.trim()) throw new Error("DEEPSEEK_API_KEY is required");
  const response = await fetch("https://api.deepseek.com/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
    signal,
  });
  if (!response.ok) {
    await response.body?.cancel();
    throw new Error(`DeepSeek HTTP ${response.status}`);
  }
  // 服务返回了 JSON，不等于它已符合 Runtime 的 Action 契约。
  const payload: unknown = await response.json();
  return payload;
}

这个函数只做一件事：带着密钥、请求体与 signal 请求 DeepSeek，返回服务给出的未知 JSON。它不知道 State，也不会执行工具。

正常调用时，apiKey 形成 Authorization 请求头；body 经 JSON.stringify 变为请求文本；fetch 返回 HTTP Response。状态成功后读取 response.json，payload 接住解析后的值，再 return 给调用方。body 中的字段由调用方提供，本函数不暗中增加会话历史。

这里有两种尚未确定的事：HTTP 成功不代表模型给出了完整答案，JSON 能解析也不代表字段符合 Action。因此返回类型保持 unknown，第二阶段再检查。

非成功 HTTP 状态会先取消尚未使用的响应体，再抛出带状态码的错误。signal 直接交给 fetch，使第 4 篇的停止通知可以到达实际网络请求；本函数不另外建立自己的计时器。DeepSeek：Chat Completions 接口

3. 用一个短入口确认连接 ​

新建 src/examples/ask-deepseek.ts，写入完整内容：

ts
import { requestDeepSeek } from "../adapters/deepseek/http.ts";
import { createRunControl } from "../runtime/run-control.ts";

const apiKey = process.env.DEEPSEEK_API_KEY?.trim();
if (!apiKey) throw new Error("DEEPSEEK_API_KEY is required");
const model = process.env.DEEPSEEK_MODEL?.trim() || "deepseek-flash";
const control = createRunControl({ timeoutMs: 30_000 });
try {
  const payload = await control.wait((signal) => requestDeepSeek(apiKey, {
    model,
    messages: [{ role: "user", content: "请只回复：连接成功" }],
    thinking: { type: "disabled" },
    stream: false,
    max_tokens: 32,
  }, signal));
  console.log(`模型原始响应（response）: ${JSON.stringify(payload, null, 2)}`);
} finally {
  control.dispose();
}

先认清三个变量：apiKey 与 model 从本机环境读取，control 复用上一章的等待控制。control.wait 启动一次 requestDeepSeek，payload 接住服务原始响应；finally 清理计时器。这里没有 Agent Loop、工具或 State。

请求的 messages 只有一条 user 消息，内容是“请只回复：连接成功”。stream:false 表示取得完整响应后再处理。thinking.disabled 显式关闭思考模式；本章不保存或回传 reasoning_content，不能只删除这一配置就认为已经支持思考工具调用。DeepSeek：思考模式及历史回传要求

运行：

bash
npm run typecheck
node --env-file=.env src/examples/ask-deepseek.ts

原始 JSON 通常含 choices 数组；在其第一项的 message.content 中应能找到回答。response.id、用量和具体措辞可能变化，不要逐字对比整份 JSON。此时只确认请求与响应链路，没有完成工具调用，也没有实现循环决策。

若出现 HTTP 401，先检查密钥；HTTP 402 检查账户余额；连接或 TLS 错误先调查网络；30 秒后停止则先确认响应是否一直没到达。不要因为任何错误都发生在这个命令里，就先改 Runtime 的状态逻辑。

第二阶段：把模型接口接到已有契约 ​

接下来有四个已有文件需要迁移：types.ts、tool.ts、tool-registry.ts、read-source-tool.ts。完成本阶段全部修改后再运行整项目检查，避免将迁移到一半的缺字段当成最终故障。

4. 保存工具调用附带的文字 ​

在 src/runtime/types.ts 中，用以下整段替换 Action，其他类型保持不变：

ts
/** 模型提出的请求。finish 仍要经过应用的完成验证。 */
export type Action =
  | { kind: "tool"; call: ToolCall; content?: string | null }
  | { kind: "finish"; answer: string }
  | { kind: "fail"; reason: string };

真实模型提出工具请求时，还可能附带“先读取文件”这样的文字。新增可选 content 保存这部分，而不是转换成 Action 时丢掉。旧脚本仍可返回只有 kind、call 的动作；循环照常整体记录 action，不需要修改。

content 是模型这次回复的文字，不是工具结果；源码仍需要等工具执行后作为 tool 消息写回。

5. 让工具同时提供说明与本地执行入口 ​

在 src/runtime/tool.ts 中，保留 ParseResult、ToolOutput，用以下两个类型替换原 Tool 与 ToolDefinition：

ts
/** 工具入口接收原始参数和本次运行的停止信号。 */
export type Tool = {
  readonly name: string;
  readonly description: string;
  readonly parameters: Record<string, unknown>;
  readonly invoke: (input: unknown, signal: AbortSignal) => Promise<ToolOutput>;
};

/** 同一个 Args 连接检查结果与执行体；signal 继续传给具体操作。 */
export type ToolDefinition<Args> = {
  name: string;
  description: string;
  parameters: Record<string, unknown>;
  parse: (input: unknown) => ParseResult<Args>;
  execute: (args: Args, signal: AbortSignal) => Promise<unknown>;
};

工具定义现在同时包含两类内容：description、parameters 告诉模型“何时使用、参数怎样写”；parse、execute 和 invoke 负责本地检查与操作。parameters 是描述参数形状的 JSON Schema 对象，不是执行函数，也不会替代 parse。

再用下面完整函数替换 defineTool：

ts
/** 封装校验顺序，使执行体只接收 parse 成功产出的参数。 */
export function defineTool<Args>(definition: ToolDefinition<Args>): Tool {
  return {
    name: definition.name,
    description: definition.description,
    parameters: structuredClone(definition.parameters),
    async invoke(input, signal) {
      signal.throwIfAborted();
      const parsed = definition.parse(input);
      if (!parsed.ok) {
        return { status: "error", code: "invalid-arguments", message: parsed.message };
      }

      // 检查函数也可能触发取消；开始实际操作前再确认一次。
      signal.throwIfAborted();
      const value = await definition.execute(parsed.value, signal);
      return { status: "ok", value };
    },
  };
}

invoke 的检查与执行顺序沿用上一章，只新增对说明与参数描述的保存；parameters 复制后放到工具对象上。后面模型适配器只提取名称、说明和参数描述，不将 invoke、parse、execute 发送给服务。

接着修改 src/runtime/tool-registry.ts：找到 byName.set 的旧语句，用下面整条语句替换，其他代码保留：

ts
byName.set(tool.name, {
  name: tool.name,
  description: tool.description,
  parameters: structuredClone(tool.parameters),
  invoke: tool.invoke,
});

这一步让注册表继续保存新字段。若只在 Tool 类型上增加字段，注册时仍只保留 name、invoke，后面就取不到给模型的说明。它们都是内存配置，不加入 State 消息。

6. 给读取工具补上准确的参数说明 ​

在 src/examples/read-source-tool.ts 中，保留顶部导入和 parseReadSourceArgs；用下面完整定义替换原 readSourceTool：

ts
/** 仍是模拟读取；执行日志只出现在校验通过后的工具体中。 */
export const readSourceTool = defineTool<ReadSourceArgs>({
  name: "read_source",
  description: "读取指定源码文件的内容；本例仅提供 src/sum.ts。",
  parameters: {
    type: "object",
    properties: { path: { type: "string", enum: [sourcePath] } },
    required: ["path"],
    additionalProperties: false,
  },
  parse: parseReadSourceArgs,
  async execute(args) {
    console.log(`[执行工具 execute] read_source 文件路径（path）=${args.path}`);
    return sourceCode;
  },
});

description 说明用途，parameters 描述“对象中必须有 path，它是字符串且只能为本例路径，不能有多余字段”。enum 表示允许值列表；required 表示必填字段；additionalProperties:false 表示不接受未声明字段。

正常模型请求应生成 {"path":"src/sum.ts"}。但是给模型一份规则，不等于任何返回都已通过本地检查；真正执行前依旧运行原来的 parseReadSourceArgs。两份规则需要保持一致：本章的声明供模型生成参数，解析器决定程序是否接受本次实际数据。

本篇使用标准接口，不启用 DeepSeek 的 Beta strict 模式。不要把普通 parameters 描述理解成服务器保证每次都严格符合，解码与本地参数检查都保留。DeepSeek：strict 模式的额外要求

7. 把内部消息转成接口消息 ​

新建 src/adapters/deepseek/protocol.ts。先写导入：

ts
import type { Action, DecisionContext } from "../../runtime/types.ts";

接着写入以下类型与完整函数，后面再追加响应解码：

ts
/** 只覆盖本章非思考、文本和单工具调用使用的消息形状。 */
export type DeepSeekMessage =
  | { role: "system" | "user"; content: string }
  | {
      role: "assistant";
      content: string | null;
      tool_calls?: {
        id: string;
        type: "function";
        function: { name: string; arguments: string };
      }[];
    }
  | { role: "tool"; tool_call_id: string; content: string };

/** 每轮从最新 Context 构造请求，不维护第二份隐藏会话。 */
export function buildDeepSeekMessages(
  context: DecisionContext,
  systemPrompt: string,
): DeepSeekMessage[] {
  const messages: DeepSeekMessage[] = [{ role: "system", content: systemPrompt }];
  for (const message of context.messages) {
    if (message.role === "user") {
      messages.push({ role: "user", content: message.content });
    } else if (message.role === "tool") {
      messages.push({
        role: "tool",
        tool_call_id: message.result.callId,
        content: JSON.stringify(message.result),
      });
    } else if (message.action.kind === "tool") {
      const { call, content } = message.action;
      messages.push({
        role: "assistant",
        content: content ?? null,
        tool_calls: [{
          id: call.id,
          type: "function",
          function: { name: call.name, arguments: JSON.stringify(call.arguments) },
        }],
      });
    } else if (message.action.kind === "finish") {
      messages.push({ role: "assistant", content: message.action.answer });
    } else {
      throw new Error("Cannot request a new decision after a fail action");
    }
  }
  return messages;
}

这个函数接收什么，返回什么 ​

buildDeepSeekMessages 接收最新 Context 和本应用的 systemPrompt，返回一份新的 DeepSeekMessage 数组。它不维护另一份隐藏会话，不向 State 反写接口数据。

DeepSeekMessage 是本章用到的接口消息形状。system 消息用来提供应用的行为说明，user 消息承载用户任务，assistant 保存模型回复或工具请求，tool 保存对应调用的结果。

正常两轮怎样转换 ​

第一次 Context 只有 user。函数先放入 systemPrompt，再把 user 内容放进去，所以服务收到 system -> user。

模型要求读取后，循环记录 assistant 请求并执行工具，将结果写为 tool。第二次 Context 有三条消息，转换后成为四条：system -> user -> assistant -> tool。注意新增的 system 是适配时加入的，不是偷偷写入 State 的新消息。

assistant 的 tool 分支将 call.id 放入 tool_calls[].id，将 call.name 放进 function.name，将 arguments 对象序列化为 JSON 字符串。tool 分支再把 result.callId 放入 tool_call_id，并将完整结果序列化为 content。于是模型知道“这份观察属于哪次请求”，而不只是收到一段没有来源的源码。

例如本地调用身份为 call_abc，发送的请求记录与结果记录必须使用同一个 call_abc。这里保留服务生成的身份，不再将真实调用固定为 read-1。 工具成功和失败结果都保留 status，失败时模型也能看到 code、message。DeepSeek：工具结果的关联字段

为什么要检查终止动作 ​

finish 转成普通 assistant 文本。fail 表示本次已终止，正常循环不会再向模型请求决策；如果外部手工构造了包含 fail 的 Context，本函数直接拒绝，避免假装仍在原任务中继续。

本章只有文本、单工具和非思考模式。这份类型没有声称覆盖图像、流式增量或思考记录。JSON.stringify 负责序列化，不是校验任意循环引用或不可表示的数据；这类错误会在决策边界失败。

8. 检查响应，并转换成 Action ​

继续在 protocol.ts 末尾追加三个检查函数：

ts
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
function record(value: unknown, label: string): Record<string, unknown> {
  if (!isRecord(value)) throw new Error(`Invalid ${label}: expected object`);
  return value;
}
function nonEmptyText(value: unknown, label: string): string {
  if (typeof value !== "string" || !value.trim()) {
    throw new Error(`Invalid ${label}: expected non-empty string`);
  }
  return value;
}

这些函数检查真实值，不使用 as Action 让编译器直接相信网络数据。record 接受非 null、非数组的对象，nonEmptyText 接受非空字符串；标签只用于说明错误发生在哪个字段。isRecord 的返回类型告诉 TypeScript：检查通过后可以按键读取这个对象。

然后追加完整解码函数：

ts
/** 不完整、错误形状和多调用都拒绝，不能挑一项悄悄执行。 */
export function decodeDeepSeekAction(payload: unknown): Action {
  const root = record(payload, "response");
  if (!Array.isArray(root.choices) || root.choices.length !== 1) {
    throw new Error("Expected exactly one model choice");
  }
  const choice = record(root.choices[0], "choice");
  const message = record(choice.message, "assistant message");
  if (message.role !== "assistant") throw new Error("Expected assistant role");
  if (message.reasoning_content != null && message.reasoning_content !== "") {
    throw new Error("This adapter requires thinking disabled");
  }
  const content = message.content;
  if (content !== null && typeof content !== "string") {
    throw new Error("Invalid assistant content");
  }
  const calls = message.tool_calls ?? [];
  if (!Array.isArray(calls)) throw new Error("Invalid tool_calls");

  if (choice.finish_reason === "tool_calls") {
    if (calls.length !== 1) throw new Error("This runtime supports one tool call per decision");
    const call = record(calls[0], "tool call");
    if (call.type !== "function") throw new Error("Unsupported tool call type");
    const fn = record(call.function, "function");
    const id = nonEmptyText(call.id, "call id");
    const name = nonEmptyText(fn.name, "tool name");
    const rawArguments = nonEmptyText(fn.arguments, "arguments JSON");
    let args: unknown;
    try { args = JSON.parse(rawArguments); }
    catch { throw new Error("Invalid tool arguments JSON"); }
    return { kind: "tool", content, call: { id, name, arguments: record(args, "arguments") } };
  }
  if (choice.finish_reason !== "stop" || calls.length !== 0) {
    throw new Error("Incomplete or unsupported model response");
  }
  return { kind: "finish", answer: nonEmptyText(content, "answer") };
}

接收的未知值来自哪里 ​

requestDeepSeek 交回 payload:unknown。本函数先确认最外层对象，再检查 choices 恰有一个选择，并取得其中的 assistant message。只有形成合法 Action，循环才会记录动作或执行工具。

这里两种 JSON 不要混淆：response.json 已解析整份 HTTP JSON，但 function.arguments 仍是服务返回的字符串，比如 "{\"path\":\"src/sum.ts\"}"。因此还要单独 JSON.parse 参数，再确认得到的是对象。

模型提出读取时 ​

正常工具响应的 finish_reason 为 tool_calls，message.tool_calls 中包含一次调用。函数检查调用种类、非空 ID、名称与参数文本，然后构造 tool Action：保留模型 content，以模型 ID、名称和解析后的参数创建 call。

此处检查“是否能形成工具请求”；它没有检查 path 是否字符串、路径是否允许，也没有自动执行。后面注册表查名称，工具 parse 检查参数，循环保存结果，仍是独立步骤。

模型给出普通答案时 ​

finish_reason 为 stop、没有工具请求且 content 是非空字符串，才转成 finish。finish 仍需通过应用完成规则，不能在这里直接返回 completed。

若同时返回多个调用，本章直接拒绝，不悄悄挑第一个。如果 finish_reason 表示截断等未完成状态，也拒绝，不执行看似能解析的半份请求。思考内容非空、角色错误、参数 JSON 不合法都会在此失败。它们属于决策输入输出边界的问题，还没有工具执行结果可写回。DeepSeek：响应字段与结束原因

/** 提供原 Dependencies.decide 接口；不自行运行工具或追加消息。 */
export function createDeepSeekDecider(options: DeepSeekOptions): Dependencies["decide"] {
  const { apiKey, model, systemPrompt, registry } = options;
  if (!apiKey.trim() || !model.trim()) throw new Error("API key and model are required");
  const tools = registry.names().map((name) => {
    const tool = registry.get(name);
    if (!tool) throw new Error(`Missing registered tool: ${name}`);
    return {
      type: "function",
      function: { name: tool.name, description: tool.description, parameters: tool.parameters },
    };
  });
  return async (context, signal) => {
    const messages = buildDeepSeekMessages(context, systemPrompt);
    console.log(`[请求模型 model] 消息角色（roles）=${messages.map((m) => m.role).join(" -> ")}`);
    const payload = await requestDeepSeek(apiKey, {
      model, messages, tools, tool_choice: "auto",
      thinking: { type: "disabled" }, stream: false, max_tokens: 1024,
    }, signal);
    const action = decodeDeepSeekAction(payload);
    if (action.kind === "tool" && context.messages.some((message) =>
      message.role === "assistant" && message.action.kind === "tool" &&
      message.action.call.id === action.call.id
    )) {
      throw new Error("Duplicate tool call id in this run");
    }
    console.log(`[模型动作 action] ${action.kind}`);
    return action;
  };
}

创建时与运行时各发生什么 ​

应用创建 decider 时交入密钥、模型名、systemPrompt 和注册表。函数先核对配置，再从注册表取出工具说明，形成接口的 tools 列表。此时还没有网络请求，也没有运行工具。

返回的函数才是 Dependencies.decide：循环调用它，传入本轮 Context 与 signal。它依次构造 messages、请求服务、检查 payload、返回 Action。声明 Dependencies["decide"] 表示返回函数必须符合已有依赖类型，不需要重写循环接口。

正常路径的数据经过哪里 ​

本轮 Context → buildDeepSeekMessages 返回 messages → requestDeepSeek 返回 payload → decodeDeepSeekAction 返回 action → 原循环接住并记录。适配器从不直接调用 executeTool，也不自己追加 State。

日志只显示实际发给服务的消息角色和解码后的动作种类。它没有打印密钥；原始响应可先在 ask-deepseek 观察。system 角色出现在这里，不意味着 State 中也多了一条 system 消息。

边界与当前限制 ​

模型可能重复调用同一工具，但每次调用需要自己的身份。返回 tool Action 后，代码从本次 Context 的历史请求中核对 ID，若已使用就拒绝，避免新结果与旧结果归属混淆。注册表在创建阶段提取说明，本章不支持运行中热更新工具清单。

提示词要求每轮最多一次调用，但不是强制机制。真正的数量限制由解码器检查；本篇没有设置未经 DeepSeek 本接口文档确认的 parallel_tool_calls 字段。非思考模式、stream:false、max_tokens:1024 都在请求体中明确设置；输出额度用完不会被当成完整答案。

/** 只检查非空答案与已确认的读取证据，不证明诊断语义正确。 */
export function hasReadEvidence(state: Readonly<State>, answer: string): boolean {
  if (!answer.trim()) return false;
  for (let index = 0; index < state.messages.length; index += 1) {
    const request = state.messages[index];
    if (request?.role !== "assistant" || request.action.kind !== "tool") continue;
    const call = request.action.call;
    if (call.name !== "read_source" || call.arguments.path !== sourcePath) continue;
    // 当前循环逐个执行工具，结果消息紧跟本次请求消息。
    const observation = state.messages[index + 1];
    if (observation?.role === "tool" && observation.result.callId === call.id &&
        observation.result.status === "ok" && observation.result.value === sourceCode) {
      return true;
    }
  }
  return false;
}

旧 hasDiagnosisEvidence 要求固定答案和固定 read-1，不能直接用于真实模型。本函数改为检查“答案非空，而且历史中存在对应请求与成功读取”。它遍历 assistant 的读取请求，再核对紧随其后的 tool 消息：ID 对应、成功且源码匹配才通过。

紧随关系来自当前单工具顺序循环；以后支持批次或并发时，要重新检查这项假设。这里的 completed 只表示本例的读取证据与非空答案检查通过，不证明诊断语义必然正确，也没有证明修改或验证修复完成。诊断内容需要阅读核对，自动质量评估后续展开。

/** 只发送请求并取得未知 JSON；不执行工具，也不修改运行状态。 */
export async function requestDeepSeek(
  apiKey: string,
  body: Record<string, unknown>,
  signal: AbortSignal,
): Promise<unknown> {
  if (!apiKey.trim()) throw new Error("DEEPSEEK_API_KEY is required");
  const response = await fetch("https://api.deepseek.com/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
    signal,
  });
  if (!response.ok) {
    await response.body?.cancel();
    throw new Error(`DeepSeek HTTP ${response.status}`);
  }
  // 服务返回了 JSON，不等于它已符合 Runtime 的 Action 契约。
  const payload: unknown = await response.json();
  return payload;
}

src/adapters/deepseek/protocol.ts ​

ts
import type { Action, DecisionContext } from "../../runtime/types.ts";

/** 只覆盖本章非思考、文本和单工具调用使用的消息形状。 */
export type DeepSeekMessage =
  | { role: "system" | "user"; content: string }
  | {
      role: "assistant";
      content: string | null;
      tool_calls?: {
        id: string;
        type: "function";
        function: { name: string; arguments: string };
      }[];
    }
  | { role: "tool"; tool_call_id: string; content: string };

/** 每轮从最新 Context 构造请求，不维护第二份隐藏会话。 */
export function buildDeepSeekMessages(
  context: DecisionContext,
  systemPrompt: string,
): DeepSeekMessage[] {
  const messages: DeepSeekMessage[] = [{ role: "system", content: systemPrompt }];
  for (const message of context.messages) {
    if (message.role === "user") {
      messages.push({ role: "user", content: message.content });
    } else if (message.role === "tool") {
      messages.push({
        role: "tool",
        tool_call_id: message.result.callId,
        content: JSON.stringify(message.result),
      });
    } else if (message.action.kind === "tool") {
      const { call, content } = message.action;
      messages.push({
        role: "assistant",
        content: content ?? null,
        tool_calls: [{
          id: call.id,
          type: "function",
          function: { name: call.name, arguments: JSON.stringify(call.arguments) },
        }],
      });
    } else if (message.action.kind === "finish") {
      messages.push({ role: "assistant", content: message.action.answer });
    } else {
      throw new Error("Cannot request a new decision after a fail action");
    }
  }
  return messages;
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
function record(value: unknown, label: string): Record<string, unknown> {
  if (!isRecord(value)) throw new Error(`Invalid ${label}: expected object`);
  return value;
}
function nonEmptyText(value: unknown, label: string): string {
  if (typeof value !== "string" || !value.trim()) {
    throw new Error(`Invalid ${label}: expected non-empty string`);
  }
  return value;
}

/** 不完整、错误形状和多调用都拒绝，不能挑一项悄悄执行。 */
export function decodeDeepSeekAction(payload: unknown): Action {
  const root = record(payload, "response");
  if (!Array.isArray(root.choices) || root.choices.length !== 1) {
    throw new Error("Expected exactly one model choice");
  }
  const choice = record(root.choices[0], "choice");
  const message = record(choice.message, "assistant message");
  if (message.role !== "assistant") throw new Error("Expected assistant role");
  if (message.reasoning_content != null && message.reasoning_content !== "") {
    throw new Error("This adapter requires thinking disabled");
  }
  const content = message.content;
  if (content !== null && typeof content !== "string") {
    throw new Error("Invalid assistant content");
  }
  const calls = message.tool_calls ?? [];
  if (!Array.isArray(calls)) throw new Error("Invalid tool_calls");

  if (choice.finish_reason === "tool_calls") {
    if (calls.length !== 1) throw new Error("This runtime supports one tool call per decision");
    const call = record(calls[0], "tool call");
    if (call.type !== "function") throw new Error("Unsupported tool call type");
    const fn = record(call.function, "function");
    const id = nonEmptyText(call.id, "call id");
    const name = nonEmptyText(fn.name, "tool name");
    const rawArguments = nonEmptyText(fn.arguments, "arguments JSON");
    let args: unknown;
    try { args = JSON.parse(rawArguments); }
    catch { throw new Error("Invalid tool arguments JSON"); }
    return { kind: "tool", content, call: { id, name, arguments: record(args, "arguments") } };
  }
  if (choice.finish_reason !== "stop" || calls.length !== 0) {
    throw new Error("Incomplete or unsupported model response");
  }
  return { kind: "finish", answer: nonEmptyText(content, "answer") };
}

src/runtime/types.ts ​

ts
import type { StopOutcome } from "./run-control.ts";

/** 模型提出的工具请求；id 标识一次调用，name 标识工具种类。 */
export type ToolCall = {
  id: string;
  name: string;
  arguments: Record<string, unknown>;
};

/** 可由程序区分的工具失败原因，不依赖错误文字匹配。 */
export type ToolErrorCode = "unknown-tool" | "invalid-arguments" | "tool-error";

/** 工具观察始终关联原请求；错误也会进入下一轮输入。 */
export type ToolResult =
  | { callId: string; status: "ok"; value: unknown }
  | { callId: string; status: "error"; code: ToolErrorCode; message: string };

/** 模型提出的请求。finish 仍要经过应用的完成验证。 */
export type Action =
  | { kind: "tool"; call: ToolCall; content?: string | null }
  | { kind: "finish"; answer: string }
  | { kind: "fail"; reason: string };

/** 本章的最小会话记录，按发生顺序追加。 */
export type Message =
  | { role: "user"; content: string }
  | { role: "assistant"; action: Action }
  | { role: "tool"; result: ToolResult };

/** 一次运行的当前事实；不同运行不能共享这个对象。 */
export type State = {
  goal: string;
  messages: Message[];
  decisions: number;
};

/** 本轮决策可见的输入；控制字段仍由 Runtime 持有。 */
export type DecisionContext = {
  readonly messages: readonly Message[];
};

/** Runtime 的退出原因，与会话里保留的事实分别表达。 */
export type Outcome =
  | { status: "completed"; answer: string }
  | {
      status: "failed";
      reason: string;
      source: "decision" | "execution" | "validation";
    }
  | { status: "budget-exhausted" }
  | StopOutcome;

export type RunResult = { state: State; outcome: Outcome };

/** 由调用方提供模型、工具和任务完成规则，循环只负责调度。 */
export type Dependencies = {
  // 接收本轮消息与取消信号，不接收 Runtime 的状态管理字段。
  decide: (context: DecisionContext, signal: AbortSignal) => Promise<Action>;
  // 取得一次请求的实际结果，必须回传同一个调用 ID。
  executeTool: (call: ToolCall, signal: AbortSignal) => Promise<ToolResult>;
  // 核对当前场景的完成证据，不把模型的 finish 直接当成成功。
  validateFinish: (state: Readonly<State>, answer: string) => boolean;
};

src/runtime/tool.ts ​

ts
/** 校验成功时交出已确认的参数；失败时不提供可执行参数。 */
export type ParseResult<Args> =
  | { ok: true; value: Args }
  | { ok: false; message: string };

/** 工具内部输出不带调用身份，身份由统一执行入口添加。 */
export type ToolOutput =
  | { status: "ok"; value: unknown }
  | { status: "error"; code: "invalid-arguments"; message: string };

/** 工具入口接收原始参数和本次运行的停止信号。 */
export type Tool = {
  readonly name: string;
  readonly description: string;
  readonly parameters: Record<string, unknown>;
  readonly invoke: (input: unknown, signal: AbortSignal) => Promise<ToolOutput>;
};

/** 同一个 Args 连接检查结果与执行体；signal 继续传给具体操作。 */
export type ToolDefinition<Args> = {
  name: string;
  description: string;
  parameters: Record<string, unknown>;
  parse: (input: unknown) => ParseResult<Args>;
  execute: (args: Args, signal: AbortSignal) => Promise<unknown>;
};

/** 封装校验顺序，使执行体只接收 parse 成功产出的参数。 */
export function defineTool<Args>(definition: ToolDefinition<Args>): Tool {
  return {
    name: definition.name,
    description: definition.description,
    parameters: structuredClone(definition.parameters),
    async invoke(input, signal) {
      signal.throwIfAborted();
      const parsed = definition.parse(input);
      if (!parsed.ok) {
        return { status: "error", code: "invalid-arguments", message: parsed.message };
      }

      // 检查函数也可能触发取消；开始实际操作前再确认一次。
      signal.throwIfAborted();
      const value = await definition.execute(parsed.value, signal);
      return { status: "ok", value };
    },
  };
}

src/runtime/tool-registry.ts ​

ts
import type { Tool } from "./tool.ts";

/** 只公开查找和列名，不允许调用方直接修改内部 Map。 */
export type ToolRegistry = {
  get: (name: string) => Tool | undefined;
  names: () => string[];
};

/** 启动时建立名称索引；重复名称是配置错误，不能静默覆盖。 */
export function createToolRegistry(tools: readonly Tool[]): ToolRegistry {
  const byName = new Map<string, Tool>();

  for (const tool of tools) {
    if (tool.name.trim().length === 0) {
      throw new Error("Tool name must not be empty");
    }
    if (byName.has(tool.name)) {
      throw new Error(`Duplicate tool: ${tool.name}`);
    }
    // 保存名称与入口的当前值，而不是交出可变的注册对象。
    byName.set(tool.name, {
      name: tool.name,
      description: tool.description,
      parameters: structuredClone(tool.parameters),
      invoke: tool.invoke,
    });
  }

  return {
    get: (name) => byName.get(name),
    names: () => [...byName.keys()],
  };
}

ts
import { defineTool } from "../runtime/tool.ts";
import type { ParseResult } from "../runtime/tool.ts";
import { sourceCode, sourcePath } from "./diagnosis-fixture.ts";

/** 本例读取体只接受这一种已经校验的参数。 */
type ReadSourceArgs = { path: string };

function parseReadSourceArgs(input: unknown): ParseResult<ReadSourceArgs> {
  if (typeof input !== "object" || input === null || Array.isArray(input)) {
    return { ok: false, message: "Arguments must be an object" };
  }
  if (!("path" in input) || typeof input.path !== "string" || input.path.trim() === "") {
    return { ok: false, message: "path must be a non-empty string" };
  }
  if (Object.keys(input).some((key) => key !== "path")) {
    return { ok: false, message: "Unexpected argument" };
  }
  if (input.path !== sourcePath) {
    return { ok: false, message: "Source path is not allowed" };
  }

  // 返回新对象，执行体不再直接接收未确认的原始输入。
  return { ok: true, value: { path: input.path } };
}

/** 仍是模拟读取；执行日志只出现在校验通过后的工具体中。 */
export const readSourceTool = defineTool<ReadSourceArgs>({
  name: "read_source",
  description: "读取指定源码文件的内容；本例仅提供 src/sum.ts。",
  parameters: {
    type: "object",
    properties: { path: { type: "string", enum: [sourcePath] } },
    required: ["path"],
    additionalProperties: false,
  },
  parse: parseReadSourceArgs,
  async execute(args) {
    console.log(`[执行工具 execute] read_source 文件路径（path）=${args.path}`);
    return sourceCode;
  },
});

src/examples/deepseek-scenario.ts ​

ts
import type { State } from "../runtime/types.ts";
import { sourcePath, sourceCode } from "./diagnosis-fixture.ts";

export const diagnosisPrompt = [
  "你是代码诊断助手。必须先调用 read_source 读取 src/sum.ts，再根据工具结果回答。",
  "每次回复最多请求一次工具调用，不伪造工具结果，不修改文件。",
  "用中文说明 sum([]) 失败的原因，并给出最小修复建议。",
].join("\n");

/** 只检查非空答案与已确认的读取证据，不证明诊断语义正确。 */
export function hasReadEvidence(state: Readonly<State>, answer: string): boolean {
  if (!answer.trim()) return false;
  for (let index = 0; index < state.messages.length; index += 1) {
    const request = state.messages[index];
    if (request?.role !== "assistant" || request.action.kind !== "tool") continue;
    const call = request.action.call;
    if (call.name !== "read_source" || call.arguments.path !== sourcePath) continue;
    // 当前循环逐个执行工具，结果消息紧跟本次请求消息。
    const observation = state.messages[index + 1];
    if (observation?.role === "tool" && observation.result.callId === call.id &&
        observation.result.status === "ok" && observation.result.value === sourceCode) {
      return true;
    }
  }
  return false;
}
